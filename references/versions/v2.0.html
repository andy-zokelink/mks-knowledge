MKS BUILDER v2.0

批处理流水线时代

从单篇手作到工业级批量生产的关键转折

2026年5月

🏭 时代概览

v2.0 标志着 MKS Builder 从「手工作坊」进入「工业流水线」时代。核心突破是场景维度的爆炸式扩展—— 从单一的场景 A（单个 MKS 提取）扩展到覆盖 A/B/D/E/F/G 六大场景的全能平台。 SQLite 本地数据库的引入终结了对 API 的绝对依赖，Graphviz 自动布局替代了手写 SVG 坐标， GitHub Pages + 飞书云盘的双轨发布机制建立了持久化的知识资产管理体系。

🎬 场景能力扩展

场景 A 单个 MKS 提取（继承优化）

保留 v1.0 的核心能力，融入新增的 9 标签统一规范和 SQLite 本地缓存，质量和速度双提升。

场景 B 大规模批量 MKS 流水线

v2.0 的核心新增能力。支持一次操作覆盖上百篇文章的批量提取。通过 delegate_task 并行调用多个 Claude Code 实例，每个子 agent 独立处理一个专题，实现真正的并行生产。

场景 D 旧版 HTML 重生成

将 v1.0 时代生成的老旧 MKS HTML 自动升级到 v2.0 的 gold template 标准。包括翻新翻转卡片样式、合并题库系统、统一导航条和响应式布局。

场景 E 跨课程合并 MKS

将来自不同专栏/课程的知识集合并为一个统一的 MKS 成果。例如将硅谷来信多个专题的知识卡片汇入共享池。

场景 F Meta-MKS 跨课思想体系重组

v2.0 最具野心的场景。跨越课程边界，从多门课程的概念池中提取高层级的思想体系——不是合并卡片，而是重组认知结构。

场景 G 播客制作

将 MKS 知识集转化为播客脚本和音频内容，实现知识的多模态输出。

🔧 核心技术升级

🗄️ SQLite 本地数据库

引入 getnote_kb.db 作为本地知识库存储，缓存 Get Notes 专栏内容。告别实时 API 查询的脆弱性，支持离线检索和批量处理。

📐 Graphviz dot 自动布局 SVG

用 Graphviz 的 dot 语言描述概念关系图，自动生成 SVG 布局，彻底替代 v1.0 的手写坐标模式。效率提升 10 倍以上，且布局质量更优。

🚀 GitHub Pages + 飞书云盘

双轨发布与持久化存档。GitHub Pages 提供公网访问的知识集展示，飞书云盘作为内部备份和团队共享的知识资产管理。

⚡ delegate_task 并行 Claude Code

通过 delegate_task 机制启动多个 Claude Code 子进程并行处理不同专题。这是 v2.0 批处理能力的核心引擎，但也带来了新的稳定性挑战。

✨ 关键设计改进

  • 9 标签统一规范：所有 MKS HTML 强制使用相同的 9 标签结构和命名，消除 v1.0 的碎片化问题
  • 选择题+简答题合并：将原本分离的两套题目标签合并为统一的「题库系统」，改善用户体验
  • 翻转卡片 Gold Template：建立翻转卡片的黄金模板（以硅谷来信1_v2 和 4-历史与文明对话.html 为基准），所有新生成和重生成的卡片样式严格对齐
  • validate_mks_html.js 校验器：自动化 HTML 质量检查脚本，检测结构完整性、标签命名、SVG 有效性等
  • 弯引号检测：自动检测并修复中文弯引号（""''）导致的编码问题
  • MCQ 答案均匀分布：强制选择题答案分布为 {0:5, 1:5, 2:5, 3:5}，避免答案模式可被猜测

⚠️ 新浮现的挑战

🧊 Claude Code 静默卡死

当传递的 JSON 数据超过约 1MB 时，Claude Code 会在不报错的情况下静默卡死，无任何超时或错误提示，导致整个批处理流水线停滞。

👻 并行 CC 进程僵尸

并行启动的 Claude Code 子进程偶尔会变成僵尸进程——已完成工作但未通知父进程，造成延迟通知和资源泄漏。

🔌 delegate_task 子 agent 中断

delegate_task 调用的子 agent 可能被父进程意外中断（如父进程超时或被用户取消），导致部分专题生成不完整。

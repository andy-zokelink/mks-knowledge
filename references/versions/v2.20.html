🔬 时代概览

v2.20 是 MKS Builder 方法论最深刻的一次范式转变。 在此之前的笔记 MKS 本质上是对已有笔记的「主题分类重组」——而课程正文 MKS 要求 逐篇通读原文、抽象概念、自建知识架构。 这不仅是技术升级，更是认知方法论的颠覆。与此同时，品控铁律体系在这一时期成型—— 「规则 + 复核 = 质量」成为不可动摇的交付准则。

📖 课程正文 MKS 方法论突破

💡 核心理念：课程正文 MKS ≠ 笔记 MKS

笔记 MKS 的路径是「主题分类」——你有已消化的笔记，按主题重组即可。 课程正文 MKS 则完全不同：你需要逐篇通读原文、在脑中建立概念空间、 识别高层抽象、构建自洽的知识架构。effort = max，一门课必须串行，不能并行拆分。

📏 大课程拆分铁律

>200 篇必修文章的课程必须拆分 5-7 个子专题。每个子专题独立生成 MKS HTML，但需保持概念体系的整体一致性。不是按篇数均分，而是按概念边界切分。

🎯 目标导向 Prompt

给 Claude Code 目标而不是微操指令。「构建这门课的概念体系」优于「列出前50篇的概念」。Claude Code 自建的概念体系优于 Hermes 强制的预设框架——放权比规范更出质量。

🏅 标杆驱动质量提升

以最优专题为参照标杆，其他专题对齐其质量标准。不是抽象的「做好一点」，而是具体的「做到和专题3一样好」。

🔄 两阶段生成恢复策略

HTML + SVG 先 commit，再补充 JavaScript 交互层。这样即使 JS 生成失败，静态内容已经安全落盘，避免从头重来。

🛡️ 品控铁律体系

⚖️ 核心原则：规则 + 复核 = 质量

单纯的规则约束不够——Claude Code 可能产出看似符合规则但实际有缺陷的内容。必须加上复核环节——验证规则是否被真正遵守。这就是品控体系的本质。

📋 交付前自查清单（8 大类）

01 代码质量（HTML 有效性、CSS 一致性）
02 MCQ（题目质量、答案分布、解析完整）
03 知识卡片（内容准确、翻转逻辑正确）
04 思维导图（结构完整、SVG 有效）
05 SVG（Graphviz 生成正确、渲染无异常）
06 导航条（9 标签齐全、链接正确）
07 响应式（移动端适配、断点合理）
08 持久化（localStorage 功能正常）

🔍 Claude Code 自检自修

交付前 Claude Code 必须逐条自查清单，发现问题自行修复。修完后重新逐条验证，确认全部通过后方可交付。这是验收闸门的硬性条件。

🌐 浏览器渲染复核

仅靠 grep 验证 HTML 源码是不够的。必须逐 tab 在浏览器中打开确认——翻转卡片是否真的可翻转？题库是否正确计分？SVG 是否正常渲染？浏览器才是最终裁判。

🔄 三大共同回归模式化

经过大量专题的反复打磨，三个最常出问题的交互模块形成了固定的品控模式：

  • 翻转卡片：检查 CSS 3D transform 兼容性、正面/背面内容映射、移动端触摸响应
  • 题库系统：验证答案均匀分布、选项随机化、计分逻辑、考试/复习模式切换
  • 思维导图：确认 SVG viewBox 正确、节点文本不溢出、连线逻辑符合概念关系

💀 重大教训沉淀

🚨 文章摘要目录 ≠ MKS

最严重的事故。某次交付中 Claude Code 仅读取了文章摘要和目录就号称完成了「概念提取」，实际零概念被真正提取。用户全量驳回，全部重做。教训：必须逐篇全文通读，effort = max。

📉 并行 CC 导致质量断崖

试图并行推进多个专题的课程正文 MKS 时，每个子 agent 对概念体系的理解片段化，产出的概念互不兼容、大量重复和遗漏。教训：课程正文 MKS 必须串行。

🖼️ 实体卡片 5K+ 需 Canvas 虚拟化

当概念卡片数量超过 5,000 张时，DOM 渲染性能急剧下降。需要 Canvas 虚拟化渲染方案，而非直接 DOM 挂载。当时仅识别问题，未解决。
